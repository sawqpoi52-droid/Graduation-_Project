# SecureCheck — منصة تدقيق ومعالجة الانكشافات الأمنية
## Automated Exposure Discovery & Remediation Engine

مشروع متكامل (Node.js + React) لفحص ومعالجة البيانات الحساسة وعناوين البريد المكشوفة على GitHub والمنصات العامة وفق سياسات الاستخدام والمعايير الأمنية المعتمدة.

---

## 🌟 الميزات الرئيسية / Key Features

1. **GitHub Automated Exposure Remediation Engine**:
   - دورة حياة منضبطة للحالات: `خطة (Dry-Run) ← موافقة المستخدم ← تنفيذ آمن ← تحقق مستقل`.
   - **فصل المنفّذ عن المُحقّق**: تقييم مستقل تماماً للنتائج لضمان المصداقية أمام لجان التحكيم والمناقشة.
   - **مصفوفة مسارات ذكية (Classification Matrix)** تصنّف الانكشاف بحسب نوعه وصلاحيات المستخدم:
     - **Lane A1**: تعديل محتوى الملفات مباشرة عبر Contents API في المستودعات المملوكة مع حماية الفروع.
     - **Lane A2**: إعادة كتابة تاريخ المستودع عبر `git-filter-repo` (الإصدار 2.47+) بنسخ عاكسة احتياطية وموافقة مشددة.
     - **Lane A3**: إدارة التعليقات في الـ Issues والـ PRs مع التحذير من سجل التعديلات.
     - **Lane A4**: إدارة خصوصية البريد على مستوى الحساب (GitHub Account Privacy).
     - **Lane B**: تقديم مقترح تعديل (Pull Request) آلي في مستودعات الغير مع تجنب الحظر والسقوط المرن.
     - **Lane C**: توليد حزم أدلة مفصلة (Evidence Packages) بصيغة Markdown للحالات التي تتطلب تواصلاً يدوياً أو تدخلاً من الدعم.
2. **أمان وتشفير متقدم**:
   - تشفير توكنات GitHub بمفتاح `AES-256-GCM`.
   - حجب كامل للبيانات الحساسة في السجلات وسجل التدقيق (Audit Logging).
   - حصر الفحص في العناوين الموثقة لحساب المستخدم (`verified=true`) فقط لمنع إساءة الاستخدام.
3. **واجهة استخدام تفاعلية وثنائية اللغة**:
   - دعم كامل للغتين العربية والإنجليزية مع اتجاه RTL متناسق.
   - عرض فوري للفروقات (Unified Diff Viewer) قبل التنفيذ.
   - وسم شفاف لبيانات الاختبار (`data_origin='seeded_test'`).

## ⚖️ القدرات والحدود التقنية / Capabilities & Limitations

انطلاقاً من الشفافية العلمية والالتزام بسياسات GitHub، يوضح الجدول التالي ما يستطيع المحرك تنفيذه وما يقع خارج نطاق الإمكانية التقنية أو القانونية:

| النطاق / Scope | ما يمكن للنظام تنفيذه آلياً (Automated Capabilities) | الحدود والقيود التقنية والقانونية (Limitations & Boundaries) |
| :--- | :--- | :--- |
| **مستودعات يملكها المستخدم (Owned Repos)** | - تعديل الملف الحالي واستبدال البريد بـ `[email removed]` (A1).<br>- إنشاء فرع وPR داخلي عند وجود حماية فروع.<br>- إعادة كتابة التاريخ باستخدام `git-filter-repo` (A2). | - بقاء البيانات في الـ Forks السابقة وعروض الـ Cache وروابط الـ PRs حتى بعد الـ Force-push.<br>- يتطلب تنظيف الـ Cache تذكرة دعم رسمي لـ GitHub يقدّمها المالك يدوياً. |
| **مستودعات لا يملكها المستخدم (Third-Party Repos)** | - عمل Fork آلي واستنساخ فرع.<br>- تعديل السطر المعني فقط.<br>- فتح Pull Request مهذب وموجز لمالك المستودع (B). | - **مستحيل تقنياً وقانونياً حذف أي محتوى مباشرة من مستودع لا تملكه**.<br>- قد يفشل الـ PR إذا كان المالك معطلاً للـ PRs أو حاصراً لها على المساهمين (يسقط المحرك تلقائياً للمسار C). |
| **بيانات الكوميتات في مستودعات الغير** | - اكتشافها وتوثيقها بدقة مع الرابط الدائم والـ Commit SHA (Lane C). | - **لا يمكن تعديل كوميت في مستودع الغير إطلاقاً**.<br>- الحل الوحيد هو تقديم حزمة الأدلة يدوياً لدعم GitHub أو المالك. |
| **طلبات إزالة البيانات الخاصة لـ GitHub** | - توليد حزمة أدلة متكاملة ومطابقة لنموذج GitHub مع الرابط ورقم السطر والمسوغ (Lane C). | - **محظور أتمتة إرسال النموذج عبر البوتات** وفق سياسة GitHub الرسمية.<br>- يجب أن يُقدّم النموذج المستخدم بنفسه لضمان الاستجابة. |
| **تعليقات الـ Issues والـ PRs** | - حذف التعليق بالكامل عبر API (A3).<br>- تعديل نص التعليق مع التحذير. | - سجل تعديلات التعليق (Edit History) في GitHub مرئي للعامة ولا يوجد API لحذفه (يتطلب حذفه يدوياً عبر الواجهة). |
| **خدمات الطرف الثالث (Hacker News)** | - اكتشاف وربط الموضع وتوثيقه (C). | - لا توجد واجهات تعديل آلية؛ يتم تقديم حزمة الأدلة للمشرفين يدوياً. |
| **حجم الملفات والبحث** | - فحص وتعديل الملفات النصية القياسية. | - بحث GitHub يقتصر على الفرع الافتراضي والملفات الأصغر من 384KB.<br>- البحث وسيلة اكتشاف وليس دليلاً قاطعاً على الإزالة. |

## 🚀 التثبيت والتشغيل / Setup & Running

### متطلبات التشغيل:
- **Node.js**: الإصدار 18 أو أحدث.
- **Python**: 3.8+ (لتشغيل أداة `git-filter-repo`).
- **Git**: 2.30+ مثبت في بيئة النظام.

### الخطوات:
```bash
# 1. تثبيت الاعتماديات للواجهة والخلفية
cd backend && npm install
cd ../frontend && npm install

# 2. بناء الواجهة الأمامية
npm run build

# 3. إعداد المتغيرات البيئية
cp ../.env.example ../.env
# قم بتعديل ملف .env وإضافة GITHUB_CLIENT_ID و GITHUB_CLIENT_SECRET

# 4. تشغيل الخادم
cd ../backend
node server.js
```
